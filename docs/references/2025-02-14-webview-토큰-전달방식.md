# WebView 토큰 전달 방식

## 개요

React Native 앱에서 WebView로 인증 토큰을 전달하는 방식을 비교하고, 최적의 방법을 선택합니다.

## 배경

하이브리드 앱에서 네이티브 앱이 소셜 로그인을 처리한 후, WebView 내의 웹 애플리케이션에 토큰을 전달해야 합니다. 이때 보안성, 구현 복잡도, 사용자 경험을 모두 고려해야 합니다.

## 토큰 전달 방식 비교

### 1. URL 파라미터 방식

WebView 로드 시 URL에 토큰을 포함시키는 방식입니다.

```typescript
// 앱에서 WebView 로드
<WebView source={{ uri: `https://web.com?token=${accessToken}` }} />
```

```typescript
// 웹에서 토큰 추출
const params = new URLSearchParams(window.location.search);
const token = params.get('token');
```

#### 장점

- 구현이 가장 단순함
- 별도의 통신 프로토콜 불필요

#### 단점

- **보안 취약**: 토큰이 URL에 노출됨
  - 브라우저 히스토리에 저장
  - 서버 로그에 기록
  - Referrer 헤더로 외부 유출 가능
- 토큰 길이 제한 (URL 최대 길이)
- 양방향 통신 불가능
- 토큰 갱신 시 페이지 리로드 필요

#### 결론

**사용 금지** - 보안상 치명적인 문제가 있어 절대 사용하면 안 됨

---

### 2. JavaScript Injection 방식

WebView 로드 후 JavaScript를 주입하여 토큰을 전달하는 방식입니다.

```typescript
// 앱에서 JS 주입
webViewRef.current?.injectJavaScript(`
  window.authToken = "${accessToken}";
  window.dispatchEvent(new Event('token-injected'));
  true;
`);
```

```typescript
// 웹에서 토큰 수신
window.addEventListener('token-injected', () => {
  const token = window.authToken;
  localStorage.setItem('accessToken', token);
});
```

#### 장점

- URL에 토큰 노출되지 않음
- 페이지 로드 후 언제든 토큰 전달 가능

#### 단점

- **단방향 통신**: 앱 → 웹만 가능
- 웹에서 앱으로 토큰 갱신 알림 불가
- 주입 타이밍 관리 필요 (페이지 로드 완료 후)
- XSS 공격에 취약할 수 있음

#### 결론

**권장하지 않음** - 양방향 통신이 필요한 경우 부적합

---

### 3. Cookie 방식

HttpOnly 쿠키를 사용하여 토큰을 공유하는 방식입니다.

```typescript
// 앱에서 쿠키 설정 (CookieManager 사용)
import CookieManager from '@react-native-cookies/cookies';

await CookieManager.set('https://web.com', {
  name: 'accessToken',
  value: accessToken,
  httpOnly: true,
  secure: true,
});
```

#### 장점

- HttpOnly 쿠키 사용 시 XSS 공격 방어
- 웹 요청 시 자동으로 토큰 포함

#### 단점

- 추가 라이브러리 필요 (`@react-native-cookies/cookies`)
- **Same-Origin 정책 제약**: 도메인이 다르면 쿠키 공유 불가
- 앱과 웹의 도메인이 일치해야 함
- 양방향 통신 불가능
- 쿠키 동기화 타이밍 이슈

#### 결론

**제한적 사용** - 도메인이 동일하고 단방향 전달만 필요한 경우에만 적합

---

### 4. postMessage 방식 (권장)

`window.postMessage`와 `window.ReactNativeWebView.postMessage`를 사용한 양방향 통신입니다.

```typescript
// 앱 → 웹: injectJavaScript로 메시지 전달
webViewRef.current?.injectJavaScript(`
  window.dispatchEvent(new MessageEvent('message', {
    data: ${JSON.stringify({ type: 'AUTH_TOKEN', payload: { accessToken, refreshToken } })}
  }));
  true;
`);

// 웹에서 수신
window.addEventListener('message', (event) => {
  if (event.data.type === 'AUTH_TOKEN') {
    localStorage.setItem('accessToken', event.data.payload.accessToken);
  }
});
```

```typescript
// 웹 → 앱: ReactNativeWebView.postMessage 사용
window.ReactNativeWebView.postMessage(
  JSON.stringify({ type: 'TOKEN_REFRESHED', payload: { accessToken, refreshToken } })
);

// 앱에서 수신
<WebView
  onMessage={(event) => {
    const message = JSON.parse(event.nativeEvent.data);
    if (message.type === 'TOKEN_REFRESHED') {
      saveTokens(message.payload);
    }
  }}
/>
```

#### 장점

- **양방향 통신**: 앱 ↔ 웹 모두 가능
- **토큰 동기화**: 웹에서 토큰 갱신 시 앱에도 알림 가능
- URL에 토큰 노출 없음
- 페이지 리로드 불필요
- 유연한 메시지 프로토콜 설계 가능
- 추가 라이브러리 불필요 (react-native-webview 기본 지원)

#### 단점

- 메시지 프로토콜 설계 필요
- 웹 코드 수정 필요 (앱 환경 감지 로직)
- 메시지 파싱 로직 필요

#### 결론

**권장** - 가장 유연하고 안전한 방식

## 방식별 비교 요약

| 방식 | 보안 | 양방향 통신 | 리로드 필요 | 구현 복잡도 | 권장 |
|------|------|------------|------------|------------|------|
| URL 파라미터 | ❌ 매우 취약 | ❌ | ✅ | 낮음 | ❌ |
| JS Injection | △ 보통 | ❌ | ❌ | 중간 | △ |
| Cookie | ✅ (HttpOnly) | ❌ | ❌ | 중간 | △ |
| **postMessage** | ✅ 안전 | ✅ | ❌ | 중간 | ✅ |

---

## 최종 선택: postMessage

### 선택 이유

1. **토큰 갱신 동기화 필수**
   - 웹에서 토큰을 갱신하면 앱의 SecureStore에도 저장해야 함
   - 양방향 통신이 가능한 postMessage만 이를 지원

2. **로그아웃 동기화**
   - 웹에서 로그아웃 시 앱에도 알려야 함
   - postMessage로 `LOGOUT` 이벤트 전송 가능

3. **보안성**
   - URL에 토큰 노출 없음
   - 앱과 웹 사이의 직접 통신

4. **사용자 경험**
   - 페이지 리로드 없이 토큰 전달
   - 빠르고 매끄러운 인증 처리

### 메시지 프로토콜 설계

| 방향 | 타입 | 페이로드 | 설명 |
|------|------|----------|------|
| 웹 → 앱 | `READY` | - | 웹 페이지 로드 완료 |
| 앱 → 웹 | `AUTH_TOKEN` | `{ accessToken, refreshToken }` | 토큰 전달 |
| 웹 → 앱 | `TOKEN_REFRESHED` | `{ accessToken, refreshToken }` | 토큰 갱신됨 |
| 웹 → 앱 | `LOGOUT` | - | 로그아웃 요청 |

### 통신 플로우

```
[앱 시작 - 로그인 완료]
        │
        ▼
┌─────────────────────────────────────────┐
│ 1. 앱: SecureStore에 토큰 저장           │
│ 2. 앱: WebView로 웹 URL 로드             │
└─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────┐
│ 3. 웹: 페이지 로드 완료                  │
│    └─▶ postMessage('READY') 전송        │
└─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────┐
│ 4. 앱: 'READY' 메시지 수신               │
│    └─▶ injectJavaScript로 토큰 전달     │
│        (AUTH_TOKEN 메시지)              │
└─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────┐
│ 5. 웹: 'AUTH_TOKEN' 메시지 수신          │
│    └─▶ localStorage에 토큰 저장         │
│    └─▶ 인증 상태 업데이트               │
└─────────────────────────────────────────┘
        │
        ▼ (토큰 만료 시)
┌─────────────────────────────────────────┐
│ 6. 웹: refreshToken으로 토큰 갱신        │
│    └─▶ postMessage('TOKEN_REFRESHED')   │
└─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────┐
│ 7. 앱: 'TOKEN_REFRESHED' 메시지 수신     │
│    └─▶ SecureStore 업데이트             │
└─────────────────────────────────────────┘
```

## 구현 시 고려사항

### 앱 환경 감지

웹에서 앱 내 WebView 환경인지 확인해야 합니다:

```typescript
const isInApp = (): boolean => {
  return typeof window !== 'undefined' &&
         window.ReactNativeWebView !== undefined;
};
```

### 메시지 유효성 검증

수신한 메시지의 형식을 검증해야 합니다:

```typescript
const parseMessage = (data: string): Message | null => {
  try {
    const message = JSON.parse(data);
    if (typeof message.type !== 'string') return null;
    return message;
  } catch {
    return null;
  }
};
```

### 타입 안정성

TypeScript를 사용하여 메시지 타입을 정의합니다:

```typescript
interface WebViewMessage<T = unknown> {
  type: 'READY' | 'AUTH_TOKEN' | 'TOKEN_REFRESHED' | 'LOGOUT';
  payload?: T;
}
```
