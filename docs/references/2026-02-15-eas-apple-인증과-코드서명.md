# EAS Apple 인증과 코드 서명

## 개요

iOS 앱을 빌드할 때 Apple Developer 계정 인증이 필요한 이유와 방법, 그리고 인증서/Provisioning Profile의 개념을 정리합니다.

## 언제 Apple 인증이 필요한가?

EAS Build가 iOS 앱을 빌드할 때, Apple Developer 계정에 접근해야 하는 상황:

| 상황 | 필요한 작업 |
|------|------------|
| 인증서 생성/갱신 | Distribution Certificate 발급 |
| 프로필 생성/갱신 | Provisioning Profile 발급 |
| 앱 스토어 제출 | App Store Connect에 빌드 업로드 |
| 기기 등록 | Ad Hoc 배포용 디바이스 UDID 등록 |

이때 EAS가 Apple에 "나는 이 계정의 권한을 가진 사람이다"를 증명해야 합니다.

## 인증 방식

### 방식 1: Apple ID 로그인 (기본)

첫 iOS 빌드 시 자동으로 Apple 계정 정보를 요청합니다:

```
? What Apple account should we use? › (Apple ID 입력)
? Password for your Apple ID: › (비밀번호 입력)

# 2FA 활성화된 경우
? Two-factor authentication code: › (인증 코드 입력)
```

입력된 정보는 EAS 서버에 암호화되어 저장됩니다.

#### 한계점

```
[Apple ID 로그인 방식]

EAS 서버 ──▶ Apple ID + Password ──▶ Apple 서버
                      │
                      ▼
                2FA 인증 코드 요청
                      │
                      ▼
                개발자 폰에 알림 ──▶ 수동으로 코드 입력
```

**문제점:**
1. **CI/CD 불가능**: GitHub Actions에서 빌드할 때 2FA 코드를 누가 입력하나?
2. **팀 계정 공유 어려움**: Apple ID 비밀번호를 팀원에게 공유해야 함
3. **세션 만료**: 일정 시간 후 다시 로그인 필요

### 방식 2: App Store Connect API Key (권장 - 팀/CI)

API Key는 **비밀번호/2FA 없이** Apple 서비스에 접근할 수 있는 인증 수단입니다.

```
[API Key 방식]

EAS 서버 ──▶ API Key (.p8 파일) ──▶ Apple 서버
                      │
                      ▼
                즉시 인증 완료 (사람 개입 없음)
```

**해결되는 문제:**
1. **CI/CD 완전 자동화**: 사람 없이 빌드/배포 가능
2. **안전한 권한 공유**: 비밀번호 대신 Key만 공유 (권한 제한 가능)
3. **세션 만료 없음**: Key가 유효한 한 계속 사용 가능

### 언제 어떤 방식을 사용하는가?

| 상황 | Apple ID | API Key | 권장 |
|------|----------|---------|------|
| 혼자 개발, 로컬 빌드 | ✅ | △ | Apple ID |
| 팀 개발, 수동 빌드 | △ | ✅ | API Key |
| CI/CD 자동 빌드 | ❌ 불가능 | ✅ | **API Key 필수** |
| 자동 스토어 배포 | ❌ 불가능 | ✅ | **API Key 필수** |

> **결론**: CI/CD를 사용하거나, 팀으로 개발한다면 API Key 설정을 권장합니다.

### API Key의 구성 요소

| 항목 | 설명 | 예시 |
|------|------|------|
| **Issuer ID** | 팀/조직 식별자 | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` |
| **Key ID** | API Key 식별자 | `ABC123XYZ` |
| **Private Key (.p8)** | 인증에 사용되는 비밀 키 | `AuthKey_ABC123XYZ.p8` |

> **주의**: `.p8` 파일은 한 번만 다운로드 가능하며, 분실 시 새로 생성해야 합니다.

### API Key 생성 방법

1. [App Store Connect](https://appstoreconnect.apple.com/) 접속
2. **사용자 및 액세스** → **통합** → **키** 탭
3. **키 생성** 클릭
4. 이름: `EAS Build Key`
5. 액세스: `Admin` 또는 `App Manager`
6. **생성** 후 `.p8` 파일 다운로드 (한 번만 가능!)
7. **Key ID**와 **Issuer ID** 저장

### EAS에 API Key 등록

```bash
eas credentials
```

```
? What do you want to do? ›
  ❯ Set up App Store Connect API Key for your Apple Team

? Issuer ID: › (Issuer ID 입력)
? Key ID: › (Key ID 입력)
? Path to the .p8 file: › ./AuthKey_XXXXX.p8
```

또는 `eas.json`에 직접 설정:

```json
{
  "submit": {
    "production": {
      "ios": {
        "ascApiKeyPath": "./keys/AuthKey_XXXXX.p8",
        "ascApiKeyIssuerId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
        "ascApiKeyId": "XXXXXXXXXX"
      }
    }
  }
}
```

> **주의**: `.p8` 파일은 `.gitignore`에 추가하여 Git에 포함되지 않도록 합니다.

## 인증서와 Provisioning Profile

### 이것들이 무엇인가?

iOS 앱이 기기에서 실행되려면 Apple의 "허가"가 필요합니다. 이 허가를 증명하는 것이 인증서와 Provisioning Profile입니다.

```
┌─────────────────────────────────────────────────────────────┐
│              Provisioning Profile 구성 요소                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. App ID (Bundle ID)     ─── 어떤 앱인지                  │
│  2. Certificate            ─── 누가 만들었는지 (개발자)      │
│  3. Device UDIDs           ─── 어떤 기기에서 실행 가능       │
│  4. Capabilities           ─── 어떤 기능 사용 가능           │
│     └── Sign in with Apple ✅                              │
│     └── Push Notifications                                 │
│     └── ...                                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 구분 | 역할 |
|------|------|
| **Distribution Certificate** | "이 개발자가 만든 앱이다"를 증명 |
| **Provisioning Profile** | "이 앱은 이 기기에서 이 기능을 사용할 수 있다"를 증명 |

### EAS의 자동 관리 (기본)

EAS Build는 기본적으로 인증서와 Provisioning Profile을 **자동으로 생성/관리**합니다.

```
첫 빌드 시:
1. Distribution Certificate 자동 생성
2. Provisioning Profile 자동 생성
3. EAS 서버에 암호화 저장

이후 빌드:
1. 저장된 인증서/프로필 재사용
2. 만료 시 자동 갱신
```

### 인증서 상태 확인

```bash
eas credentials
```

```
? What do you want to do? ›
  ❯ Manage credentials
    ❯ iOS
      ❯ View credentials

Distribution Certificate:
  Serial: XXXXXXXXXX
  Expiry: 2026-02-15

Provisioning Profile:
  Name: com.growit.mobile AppStore
  Expiry: 2026-02-15
  Capabilities: Sign in with Apple, Push Notifications
```

### 수동 인증서 사용 (선택)

기존 인증서를 사용해야 하는 경우:

```bash
eas credentials
```

```
? What do you want to do? ›
  ❯ Manage credentials
    ❯ iOS
      ❯ Distribution Certificate
        ❯ Upload a certificate

? Path to the .p12 file: › ./Certificates.p12
? Password for the certificate: › (비밀번호 입력)
```

### Capability 추가 시 프로필 갱신

Sign in with Apple 같은 Capability를 Apple Developer 콘솔에서 추가한 경우, Provisioning Profile을 갱신해야 합니다:

```bash
eas credentials
```

```
? What do you want to do? ›
  ❯ Manage credentials
    ❯ iOS
      ❯ Provisioning Profile
        ❯ Create or regenerate profile
```

EAS가 Apple Developer 콘솔의 설정을 기반으로 새 프로필을 자동 생성합니다.
