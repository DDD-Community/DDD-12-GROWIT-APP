   # Expo 개발 워크플로우: 빌드 vs 핫 리로드

## 개요

EAS Build로 앱을 빌드한 후, 실제 개발은 어떻게 진행되는지 정리합니다. 핵심은 **대부분의 코드 변경은 핫 리로드로 즉시 반영**된다는 것입니다.

## 핵심 개념

EAS Build는 **앱 껍데기(네이티브 코드)**를 만드는 것이고, 개발 중에는 **핫 리로드**로 React 코드를 즉시 반영합니다.

| 변경 대상 | EAS 빌드 필요 | 핫 리로드 |
|----------|--------------|----------|
| React/JS 코드 (UI, 로직) | ❌ 불필요 | ✅ 즉시 반영 |
| 네이티브 패키지 추가 | ✅ 필요 | ❌ 불가능 |
| app.json 설정 변경 | ✅ 필요 | ❌ 불가능 |

## 전체 개발 플로우

```
[1회] EAS Build로 Development Build 생성 (5-30분)
              │
              ▼
      시뮬레이터/기기에 앱 설치
              │
              ▼
┌─────────────────────────────────────────────┐
│  터미널: npx expo start --dev-client        │
│                                             │
│  개발 서버 실행됨 (Metro Bundler)            │
└─────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────┐
│  시뮬레이터에서 Development Build 앱 실행    │
│              │                              │
│              ▼                              │
│  개발 서버에 자동 연결                       │
│              │                              │
│              ▼                              │
│  VS Code에서 코드 수정 → 저장               │
│              │                              │
│              ▼ (0.5초)                      │
│  화면에 즉시 반영 (핫 리로드)                │
└─────────────────────────────────────────────┘
              │
              ▼ (네이티브 패키지 추가 시에만)
              │
      EAS Build 다시 실행 → 위 과정 반복
```

## 실제 개발 세션

### 1. Development Build 설치 (최초 1회)

```bash
# 빌드 완료 후 시뮬레이터에 설치
eas build:run --platform ios
```

### 2. 개발 서버 실행 (매일)

```bash
npx expo start --dev-client
```

터미널에 표시되는 내용:

```
Metro waiting on exp://192.168.0.10:8081
› Press i │ open iOS simulator
› Press a │ open Android emulator
› Press r │ reload app
› Press m │ toggle menu
```

### 3. 앱에서 개발 서버 연결

시뮬레이터에서 Development Build 앱을 열면 자동으로 로컬 개발 서버를 감지합니다:

```
┌─────────────────────────────────────┐
│   Development Build                 │
│                                     │
│   Recently opened:                  │
│   • localhost:8081  ← 클릭하여 연결  │
│                                     │
└─────────────────────────────────────┘
```

### 4. 핫 리로드로 개발

연결 후에는 코드 수정 시 자동으로 화면에 반영됩니다:

```
VS Code: 로그인 버튼 색상 변경 → 저장
              │
              ▼ (0.5초)
              │
시뮬레이터: 버튼 색상 즉시 변경됨
```

## 언제 재빌드가 필요한가?

### 재빌드 **불필요** (핫 리로드로 즉시 확인)

- 화면 UI 수정
- 컴포넌트 스타일 변경
- 비즈니스 로직 수정
- API 호출 코드 변경
- 상태 관리 코드 수정
- 라우팅 변경
- 새 화면 추가

### 재빌드 **필요**

- `yarn add`로 **네이티브 모듈** 추가
  - 예: `expo-apple-authentication`, `react-native-webview`
- `app.json` 설정 변경 (bundleIdentifier, plugins 등)
- `eas.json` 설정 변경

## 실제 프로젝트 예시: 소셜 로그인 구현

```
1. 초기 빌드 (1회, 10-30분)
   └── expo-apple-authentication, expo-secure-store 등 설치 후 빌드

2. 로그인 화면 개발 (핫 리로드)
   ├── 로그인 버튼 UI 수정 → 즉시 반영
   ├── 버튼 스타일 변경 → 즉시 반영
   └── 로그인 로직 수정 → 즉시 반영

3. 토큰 저장 로직 개발 (핫 리로드)
   ├── SecureStore 저장 코드 → 즉시 반영
   └── 에러 처리 추가 → 즉시 반영

4. 카카오 로그인 추가 시 (재빌드 필요)
   └── @react-native-seoul/kakao-login 설치 → EAS Build

5. 카카오 로그인 화면 개발 (핫 리로드)
   └── 이후 UI/로직 수정 → 즉시 반영
```

## 개발 시간 요약

| 작업 | 빈도 | 소요 시간 |
|------|------|----------|
| EAS Build | 네이티브 패키지 추가 시 | 5-30분 |
| 개발 서버 실행 | 매일 시작 시 | 5초 |
| 코드 수정 → 화면 확인 | 수시로 | **즉시** |

## Expo Go vs Development Build

| 항목 | Expo Go | Development Build |
|------|---------|-------------------|
| 설치 | App Store에서 다운로드 | EAS Build로 직접 생성 |
| 네이티브 모듈 | ❌ 제한적 | ✅ 모든 모듈 사용 가능 |
| Apple 로그인 테스트 | ❌ 불가능 | ✅ 가능 |
| 핫 리로드 | ✅ | ✅ |

## 결론

> **대부분의 개발 시간은 핫 리로드로 진행됩니다.** EAS Build는 처음 한 번과 네이티브 패키지 추가 시에만 필요합니다.
