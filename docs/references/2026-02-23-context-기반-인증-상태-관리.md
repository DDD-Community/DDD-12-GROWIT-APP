# React Context 기반 인증 상태 관리

## 개요

React Native Expo 앱에서 인증 상태를 전역적으로 공유하기 위해 React Context를 사용하는 패턴을 정리합니다.
기존 커스텀 훅 방식에서 발생한 상태 동기화 문제를 해결한 방법을 기록합니다.

## 문제 상황

### 기존 방식의 문제

각 컴포넌트에서 `useAuth()` 훅을 호출하면 독립적인 상태가 생성됨:

```typescript
// 문제가 있던 기존 코드
export const useAuth = () => {
  const [state, setState] = useState<AuthState>({
    isLoading: true,
    isAuthenticated: false,
    tokens: null,
  });

  // 각 컴포넌트마다 독립적인 state가 생성됨
  // login() 호출해도 다른 컴포넌트의 state는 갱신되지 않음
};
```

**증상**: 로그인 성공 후에도 `_layout.tsx`의 라우팅 로직이 인증 상태 변경을 감지하지 못함

## 해결 방법: Context 기반 전역 상태

### AuthContext 구현

```typescript
// src/lib/auth/useAuth/AuthContext.tsx
import { createContext, useContext, useState, useEffect, useCallback, ReactNode } from 'react';
import { getTokens, saveTokens, removeTokens, type Tokens } from './tokenStorage';

export interface AuthState {
  isLoading: boolean;
  isAuthenticated: boolean;
  tokens: Tokens | null;
}

export interface AuthActions {
  login: (tokens: Tokens) => Promise<void>;
  logout: () => Promise<void>;
  refreshAuth: () => Promise<void>;
}

const AuthContext = createContext<(AuthState & AuthActions) | null>(null);

export const AuthProvider = ({ children }: { children: ReactNode }) => {
  const [state, setState] = useState<AuthState>({
    isLoading: true,
    isAuthenticated: false,
    tokens: null,
  });

  // 앱 시작 시 저장된 토큰 확인
  useEffect(() => {
    const initAuth = async () => {
      const tokens = await getTokens();
      setState({
        isLoading: false,
        isAuthenticated: !!tokens,
        tokens,
      });
    };
    initAuth();
  }, []);

  const login = useCallback(async (tokens: Tokens) => {
    await saveTokens(tokens);
    setState({
      isLoading: false,
      isAuthenticated: true,
      tokens,
    });
  }, []);

  const logout = useCallback(async () => {
    await removeTokens();
    setState({
      isLoading: false,
      isAuthenticated: false,
      tokens: null,
    });
  }, []);

  const refreshAuth = useCallback(async () => {
    const tokens = await getTokens();
    setState({
      isLoading: false,
      isAuthenticated: !!tokens,
      tokens,
    });
  }, []);

  return (
    <AuthContext.Provider value={{ ...state, login, logout, refreshAuth }}>
      {children}
    </AuthContext.Provider>
  );
};

export const useAuth = (): AuthState & AuthActions => {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within AuthProvider');
  }
  return context;
};
```

### _layout.tsx에서 Provider 적용

```typescript
// src/app/_layout.tsx
import { AuthProvider } from '@/lib/auth/useAuth';

function RootLayoutNav() {
  const { isLoading, isAuthenticated } = useAuth();
  const router = useRouter();
  const segments = useSegments();

  useEffect(() => {
    if (isLoading) return;

    const inAuthGroup = segments[0] === '(auth)';
    const inMainGroup = segments[0] === '(main)';

    if (!isAuthenticated && !inAuthGroup) {
      router.replace('/(auth)/login');
    } else if (isAuthenticated && !inMainGroup) {
      router.replace('/(main)');
    }
  }, [isLoading, isAuthenticated, segments, router]);

  // ...
}

export default function RootLayout() {
  return (
    <AuthProvider>
      <RootLayoutNav />
    </AuthProvider>
  );
}
```

## 핵심 포인트

### 1. 상태 공유
- `AuthProvider`가 최상위에서 단일 상태를 관리
- 모든 하위 컴포넌트가 동일한 상태 참조

### 2. 자동 동기화
- `login()` 호출 시 `setState`가 실행되면 모든 구독 컴포넌트가 리렌더링
- `_layout.tsx`의 `useEffect`가 상태 변경을 감지하여 라우팅 처리

### 3. AuthState 설계
- **토큰만 저장**: `user` 정보는 AuthState에 포함하지 않음
- **필요시 API 호출**: 사용자 정보는 별도 API로 필요할 때 조회

```typescript
// 권장하는 AuthState 구조
interface AuthState {
  isLoading: boolean;
  isAuthenticated: boolean;
  tokens: Tokens | null;
  // user 정보는 포함하지 않음
}
```

## 라우팅 로직

```typescript
const inAuthGroup = segments[0] === '(auth)';
const inMainGroup = segments[0] === '(main)';

if (!isAuthenticated && !inAuthGroup) {
```
